## ১. ভূমিকা (Agent Tooling Policy)

কোন এআই এজেন্ট তার কাজের প্রয়োজনে ফাইল সিস্টেমে কোন কোন টুল ব্যবহার করতে পারবে এবং কোথায় তার এক্সেস সীমিত থাকবে, তা এই নথিতে সুনির্দিষ্ট করা হলো।

---

## ২. এজেন্টভিত্তিক অনুমোদিত টুলসের তালিকা (Tool Access Matrix)

| এআই এজেন্ট | অনুমোদিত টুলস | সীমাবদ্ধতা / রেস্ট্রিকশন |
|---|---|---|
| **AI-BA** | `view_file`, `write_to_file`, `replace_file_content` | শুধুমাত্র `01-PRODUCT-AND-BUSINESS` ও ডক ফাইলে সীমাবদ্ধ। সোর্স কোড এডিট নিষিদ্ধ। |
| **AI-Architect** | `view_file`, `write_to_file`, `replace_file_content` | শুধুমাত্র `02-ARCHITECTURE-AND-DESIGN` ও ডিজাইন স্পেক্সে অ্যাক্সেস। |
| **AI-Backend** | সমস্ত কোড এডিট টুলস ও লোকাল টেস্ট রান টুলস | সোর্স কোডে `run_command` দিয়ে শুধুমাত্র ডকার কন্টেইনারের ভেতরে `docker compose exec backend ./vendor/bin/pint` ও `docker compose exec backend php artisan test` চালানো যাবে। হোস্ট পিসিতে সরাসরি বা প্রোডাকশন ডাটাবেজে কমান্ড নিষিদ্ধ। |
| **AI-Frontend** | সমস্ত ফ্রন্টএন্ড কোড এডিট টুলস | `npm run lint`, `npm run type-check` ও টেস্ট চালানো যাবে। কোনো ইনলাইন সিএসএস লেখার অনুমতি নেই। |
| **AI-Database** | ডাটাবেজ মাইগ্রেশন ও স্কিমা এডিট টুলস | কোনো `DROP TABLE` বা `TRUNCATE` স্টেটমেন্ট চালানোর অনুমতি নেই। |
| **AI-QA** | টেস্ট স্ক্রিপ্ট জেনারেশন ও টেস্ট রান টুলস | শুধুমাত্র `tests/` ডিরেক্টরি এবং টেস্ট এক্সিকিউশন রিপোর্ট তৈরিতে প্রযোজ্য। |
