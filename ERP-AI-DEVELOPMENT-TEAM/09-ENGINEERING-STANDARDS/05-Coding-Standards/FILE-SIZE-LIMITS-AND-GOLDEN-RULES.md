## ১. ভূমিকা ও মূল দর্শন (Core Philosophy)

একটি বড় এন্টারপ্রাইজ সিস্টেমে যখন ফাইলগুলোতে শত শত বা হাজার লাইন কোড লেখা হয়, তখন তৈরি হয় **"God Files / Spaghetti Code"**। এর ফলে:
1. কোড পড়া ও রিভিউ করা অসম্ভব হয়ে পড়ে।
2. কোডের ভেতর রিগ্রেশন বাগ তৈরি হয় এবং টেস্ট কভারেজ ভেঙে যায়।
3. একাধিক ডেভেলপার কাজ করার সময় গিট কনফ্লিক্ট দেখা দেয়।

TraceFlow-RMG প্ল্যাটফর্মে অফিসিয়াল ফ্রেমওয়ার্ক স্ট্যান্ডার্ড (Laravel 13 ও React 19) এবং সফটওয়্যার ইঞ্জিনিয়ারিংয়ের **Clean Code / Single Responsibility Principle (SRP)** অনুযায়ী প্রতিটি ফাইল ও মেথডের জন্য কঠোর **লাইন লিমিট এবং গোল্ডেন রুলস** নির্ধারণ করা হয়েছে।

## ২. ব্যাকএন্ড লাইন লিমিট ও গোল্ডেন রুলস (Laravel 13 & PHP 8.3+)

অফিসিয়াল [Laravel Best Practices](https://laravel.com/docs) এবং পিএইচপি স্ট্যান্ডার্ড রেকমেন্ডেশন (PSR-12) অনুযায়ী ব্যাকএন্ড ফাইলের সীমা:

```
├──────────────────────────┬──────────────┬──────────────┬───────────────┤

├──────────────────────────┼──────────────┼──────────────┼───────────────┤

│ Controller Method (Action)│ ১০ - ১৫ লাইন  │ ২০ লাইন      │ লজিক Domain Service-এ সরাতে হবে│
│ Domain Service           │ ১২০ - ১৮০ লাইন│ ২৫০ লাইন     │ সাব-সার্ভিসে স্প্লিট করতে হবে │

│ Eloquent Model           │ ৮০ - ১৫০ লাইন │ ২০০ লাইন     │ Trait / Scope-এ ভাগ করতে হবে  │
│ FormRequest (Validation) │ ৩০ - ৬০ লাইন  │ ১০০ লাইন     │ কাস্টম রুল অবজেক্ট বানাতে হবে  │

│ Database Migration       │ ৩০ - ৭০ লাইন  │ ১০০ লাইন     │ টেবিল স্প্লিট করতে হবে        │
```

### ব্যাকএন্ডের ৪টি গোল্ডেন রুলস (Backend Golden Rules):
1. **[RULE-B1] Skinny Controller (ম্যাক্সিমাম ২০ লাইন প্রতি মেথড):**
   - কন্ট্রোলারে কোনো বিজনেস লজিক, ডাটাবেজ কোয়েরি (`Model::where`), বা ভ্যালিডেশন লেখা নিষিদ্ধ।
   - ফ্লো: `FormRequest (Validation)` -> `Controller (1-2 lines)` -> `Domain Service` -> `JsonResource`।
2. **[RULE-B2] Single Responsibility Principle (ম্যাক্সিমাম ২৫০ লাইন প্রতি সার্ভিস):**
   - একটি সার্ভিস শুধুমাত্র একটি কাজ করবে (যেমন: `MarkerCalculationService` শুধুমাত্র মার্কার হিসাব করবে, বারকোড পিডিএফ জেনারেট করবে না)।
3. **[RULE-B3] Early Return Pattern (নেস্টেড `if-else` পরিহার):**
   - মেথডের ভেতর ৩ স্তরের বেশি নেস্টেড `if` লেখা নিষিদ্ধ। কোনো শর্ত ফেইল করলে তাৎক্ষণিক `return` অথবা কাস্টম এক্সেপশন থ্রো করতে হবে।
4. **[RULE-B4] জিরো রোবোটিক কমেন্টস ও ন্যাচারাল নেমিং:**
   - ফাংশন কী করছে তা কোড দেখেই বোঝা যেতে হবে। কমেন্ট শুধুমাত্র জটিল আরএমজি অ্যালগরিদম ব্যাখ্যা করবে (যেমন: `// Deduct 2% allowance for Lycra shrinkage`)।

## ৩. ফ্রন্টএন্ড লাইন লিমিট ও গোল্ডেন রুলস (React 19 & TypeScript)

অফিসিয়াল [React Documentation (react.dev)](https://react.dev) এবং আধুনিক কম্পোনেন্ট আর্কিটেকচার অনুযায়ী ফ্রন্টএন্ড ফাইলের সীমা:

```

├──────────────────────────┼──────────────┼──────────────┼───────────────┤
│ UI Component (Atomic)    │ ৪০ - ৮০ লাইন  │ ১২০ লাইন     │ ছোট কম্পোনেন্টে ভাঙতে হবে     │
```

### ফ্রন্টএন্ডের ৪টি গোল্ডেন রুলস (Frontend Golden Rules):
1. **[RULE-F1] শতভাগ জিরো ইনলাইন সিএসএস (Zero Inline CSS):**
   - কোনো পরিস্থিতিতেই JSX-এ `style={{ ... }}` ব্যবহার করা যাবে না। স্টাইলিং হবে সেন্ট্রালাইজড `@/components/ui/` এবং CSS Modules দিয়ে।
2. **[RULE-F2] প্রেজেন্টেশনাল বনাম কন্টেইনার কম্পোনেন্ট বিভাজন:**
   - একটি পেজ ফাইলে JSX রেন্ডারিং, সার্ভার ডাটা ফেচিং এবং জটিল স্টেট একসাথে স্তূপ করা যাবে না।
   - ডাটা ফেচিং থাকবে কাস্টম হুকে (`useOrdersQuery.ts`), বিজনেস লজিক থাকবে হুকে, এবং মূল পেজে থাকবে শুধুমাত্র সাব-কম্পোনেন্ট লেআউট।
3. **[RULE-F3] ২৫০ লাইনের বেশি কোনো পেজ কম্পোনেন্ট নয়:**
   - কোনো পেজের আকার ২৫০ লাইন ছাড়িয়ে গেলে তা বাধ্যতামূলকভাবে সাব-কম্পোনেন্টে (যেমন: `OrderSummaryCard.tsx`, `ColorSizeMatrixDrawer.tsx`, `BOMGrid.tsx`) বিভক্ত করতে হবে।
4. **[RULE-F4] অফিশিয়াল রিঅ্যাক্ট ১৯ হুক্স ও ক্লিনআপ:**
   - প্রতিটি `useEffect` বা ইভেন্ট লিসেনারে অবশ্যই প্রপার ক্লিনআপ ফাংশন (`return () => unsubscribe()`) থাকতে হবে যাতে মেমরি লিক না হয়।

## ৪. মেথড ও ফাংশন সাইজ সীমা (Functions / Methods Density)

- **সর্বোচ্চ প্যারামিটার সংখ্যা:** ৩টি। ৩টির বেশি প্যারামিটার প্রয়োজন হলে বাধ্যতামূলকভাবে DTO (PHP) অথবা Object Interface (TypeScript) পাস করতে হবে:
  ```php
  // ❌ ভুল (৫টি প্যারামিটার)
  public function createOrder($buyer, $style, $qty, $date, $price) { ... }

  // ✅ সঠিক (DTO / Type-safe Object)
  public function createOrder(OrderBookingData $data): BuyerOrder { ... }
  ```
- **সাইক্লোম্যাটিক কমপ্লেক্সিটি (Cyclomatic Complexity):** কোনো একক মেথডে সাইক্লোম্যাটিক কমপ্লেক্সিটি ১০-এর বেশি হতে পারবে না।

## ৫. সিআই পাইপলাইন ও কোড কোয়ালিটি এনফোর্সমেন্ট

TraceFlow-RMG-এর গিট হুক ও CI/CD পাইপলাইনে নিচের টুলগুলো দিয়ে স্বয়ংক্রিয়ভাবে লাইন লিমিট পরীক্ষা করা হবে:

1. **PHPStan / Laravel Pint (Backend):**
   - লেভেল ৮ স্ট্রিক্ট স্ট্যাটিক অ্যানালিসিস।
   - ২৫০ লাইনের বেশি সার্ভিস বা ১২০ লাইনের বেশি কন্ট্রোলার পুশ করলে পিআর (PR) ফেইল করবে।
2. **ESLint / Prettier / TypeScript Strict (Frontend):**
   - `max-lines`: `['error', { max: 250, skipComments: true, skipBlankLines: true }]`।
   - কোনো ফাইলে ইনলাইন স্টাইল (`react/forbid-component-props`) বা ২৫০ লাইনের অতিরিক্ত কোড থাকলে বিল্ড ব্লক হবে।
