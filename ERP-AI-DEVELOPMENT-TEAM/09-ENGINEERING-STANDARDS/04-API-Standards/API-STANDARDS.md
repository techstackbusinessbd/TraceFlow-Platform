## ১. ভূমিকা ও উদ্দেশ্য (API Philosophy)

TraceFlow-RMG প্ল্যাটফর্মের ব্যাকএন্ড এপিআই শুধু ওয়েব অ্যাপ্লিকেশনের সাথেই যোগাযোগ করে না; এটি কারখানার ফ্লোরে থাকা বারকোড স্ক্যানার টার্মিনাল, ট্যাবলেট ডিভাইস, ইলেকট্রনিক অ্যান্ডন ডিসপ্লে বোর্ড এবং থার্ড-পার্টি কমার্শিয়াল অ্যাকাউন্টিং সফটওয়্যারের সাথে সংযুক্ত থাকে।

এই কারণে প্রতিটি এপিআই হতে হবে: **প্রেডিক্টেবল (Predictable), সেলফ-ডকুমেন্টেড (OpenAPI 3.0 Compliance), উচ্চ-গতিসম্পন্ন এবং সংস্করণ-নিয়ন্ত্রিত (Version Controlled)।**

## ২. ইউআরএল ডিজাইন ও এন্ডপয়েন্ট কনভেনশন (URI Design)

### ২.১ ভার্সনিং নিয়ম
সমস্ত এপিআই এন্ডপয়েন্ট অবশ্যই ইউআরএল পাথ ভার্সনিং দিয়ে শুরু হবে:
* **ফরম্যাট:** `/api/v1/{module}/{resources}`
* *উদাহরণ:* `/api/v1/cutting/bundle-cards`

### ২.২ রিসোর্স রাউটিং ও এইচটিটিপি ভার্বস
কোনো এপিআই পাথে অ্যাকশন বা ভার্ব (যেমন: `/getBundles` বা `/deleteOrder`) ব্যবহার করা যাবে না। প্রমিত এইচটিটিপি মেথড ব্যবহার করতে হবে:

| মেথড | ইউআরএল প্যাটার্ন | বিবরণ ও ব্যবহার | স্ট্যাটাস কোড |
|---|---|---|---|
| `GET` | `/api/v1/cutting/bundles` | বান্ডেল সমূহের পেজিনেটেড তালিকা সংগ্রহ | `200 OK` |
| `GET` | `/api/v1/cutting/bundles/{id}` | নির্দিষ্ট একটি বান্ডেলের পুঙ্খানুপুঙ্খ তথ্য | `200 OK` |
| `POST` | `/api/v1/cutting/bundles` | নতুন বান্ডেল কার্ড তৈরি | `201 Created` |
| `PUT` | `/api/v1/cutting/bundles/{id}` | সম্পূর্ণ বান্ডেল রিসোর্স প্রতিস্থাপন | `200 OK` |
| `PATCH`| `/api/v1/cutting/bundles/{id}/status` | আংশিক আপডেট (যেমন: স্ট্যাটাস পরিবর্তন) | `200 OK` |
| `DELETE`| `/api/v1/cutting/bundles/{id}` | রিসোর্স সফট ডিলিট / আর্কাইভ | `200 OK` / `204 No Content` |

## ৩. ফিল্টারিং, সর্টিং ও পেজিনেশন (Query Parameters)

বড় ডাটাবেজ টেবিলে কুয়েরি করার সময় মেমোরি ওভারফ্লো ঠেকাতে নিচের স্ট্যান্ডার্ড প্যারামিটার বাধ্যতামূলক:

1. **পেজিনেশন:** ডিফল্ট পেজ সাইজ হবে ২০। সর্বোচ্চ অনুমোদিত সাইজ ১০০।
   - প্যারামিটার: `?page=1&per_page=20`
2. **সর্টিং:** প্লাস/মাইনাস বা ফিল্ড ভিত্তিক।
   - প্যারামিটার: `?sort=-created_at` (ডিসেন্ডিং) অথবা `?sort=line_id` (অ্যাসেন্ডিং)
3. **ফিল্টারিং:** সরাসরি ফিল্ড নাম ব্যবহার করে:
   - `?filter[status]=IN_SEWING&filter[buyer_id]=12`

## ৪. নিরাপত্তা, অথেনটিকেশন ও রেট লিমিটিং (Security & Rate Limits)

* **টোকেন সিস্টেম:** লারাভেল স্যাঙ্কটাম (Laravel Sanctum) অথবা পাসপোর্ট ভিত্তিক বেয়ারার টোকেন (`Authorization: Bearer <token>`).
* **ফ্লোর স্ক্যানিং রেট লিমিট:** 
  - ফ্লোর টার্মিনালগুলোর জন্য প্রতি মিনিটে সর্বোচ্চ ৬০০ রিকোয়েস্ট (যাতে হাই-স্পিড স্ক্যানিং বাধাগ্রস্ত না হয়)।
  - পাবলিক বা অ্যাডমিন এপিআইতে প্রতি মিনিটে সর্বোচ্চ ৬০ রিকোয়েস্ট।
* **হেডার রিকোয়ারমেন্টস:**
  - `Accept: application/json`
  - `Content-Type: application/json`

## ৫. সার্ভার-সাইড ভ্যালিডেশন ও ত্রুটি রেসপন্স ফরম্যাট (Server-Side Validation Standards)

* **জিরো ব্রাউজার ভ্যালিডেশন:** ক্লায়েন্ট ফর্মে কোনো ব্রাউজার ডিফল্ট HTML5 ভ্যালিডেশন টুলটিপ ব্যবহার করা যাবে না। সমস্ত ভ্যালিডেশন ব্যাকএন্ড FormRequest দ্বারা পরিচালিত হবে।
* **ভ্যালিডেশন ফেইলিওর ফরম্যাট (`422 Unprocessable Entity`):**
```json
{
  "message": "The given data was invalid.",
  "errors": {
    "name": ["The company legal name field is required."],
    "code": ["The company code format is invalid."]
  }
}
```
* ফ্রন্টএন্ড এই ফিল্ড-লেভেল এররগুলোকে পার্স করে ইনপুটের নিচে সরাসরি লাল টেক্সটে প্রদর্শন করবে।
