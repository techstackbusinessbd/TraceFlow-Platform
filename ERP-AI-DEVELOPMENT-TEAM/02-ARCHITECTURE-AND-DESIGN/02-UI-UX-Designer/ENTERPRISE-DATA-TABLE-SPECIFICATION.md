## ১. ভূমিকা ও উদ্দেশ্য (Architecture Overview)

তৈরি পোশাক শিল্প (RMG ERP) ডেটা-নিবিড় (Data-Intensive)। এখানে একটি একক ফ্যাক্টরিতে প্রতিদিন হাজার হাজার কাটিং বান্ডেল, সুইং লাইনের আওয়ারলি আউটপুট, ফেব্রিক রোল বারকোড এবং মার্চেন্ডাইজিং পিও রো পর্যবেক্ষণ ও সম্পাদনা করতে হয়। 

সাধারণ সাধারণ টেবিল কম্পোনেন্ট হাজার হাজার রো রেন্ডার করতে গিয়ে ব্রাউজারে মেমরি লিক এবং ল্যাগ তৈরি করে। TraceFlow-RMG-তে এই সমস্যা চিরতরে দূর করতে **TanStack Table v8 (Headless Core) + TanStack Virtual (Virtualization) + React 19 + TypeScript** সমন্বয়ে একটি হাই-পারফরম্যান্স **High-Density Data Grid Engine** প্রতিষ্ঠা করা হয়েছে।

### মূল ইনভ্যারিয়েন্টস:
1. **৬০ FPS স্মুথ পারফরম্যান্স:** ১০,০০০+ রো থাকলেও ভার্চুয়ালাইজেশনের মাধ্যমে DOM-এ শুধুমাত্র দৃশ্যমান ২০-৩০টি রো রেন্ডার হবে।
2. **জিরো ইনলাইন সিএসএস:** স্টাইলিং হবে সেন্ট্রালাইজড সিএসএস মডিউল ও ডিজাইন টোকেন চালিত।
3. **কিবোর্ড ফার্স্ট নেভিগেশন:** এক্সেলের মতো `Tab`, `Arrow Keys`, `Enter` দিয়ে দ্রুত ডাটা ব্রাউজ ও ইন-লাইন এডিট করা যাবে।
4. **একক সোর্স অব ট্রুথ:** পুরো প্ল্যাটফর্মে টেবিলের জন্য একটিই রিয়্যূজেবল কম্পোনেন্ট থাকবে: `<DataTable<TData> />`।

## ৪. কোর ফাংশনালিটি ও এন্টারপ্রাইজ রিকোয়ারমেন্টস

### ৪.১ পিন্ড কলাম ও ফ্রিজ প্যান (Fixed / Pinned Columns)
বড় আরএমজি টেবিলে ১৫-২০টি কলাম (Style, PO, Season, Fabric, GSM, Color, Size, Order Qty, Cut Qty, Sew Qty, Ship Date ইত্যাদি) থাকে।
- স্ক্রিনের বামপাশের প্রথম ১ বা ২টি কলাম (`Buyer Order No`) সর্বদা স্টিকি থাকবে।
- ডানপাশের শেষ কলাম (`Action Menu / Dropdown`) সর্বদা ডানপ্রান্তে স্টিকি থাকবে।
- অনুভূমিক স্ক্রোল করার সময় এই কলামগুলোর নিচে একটি সূক্ষ্ম ড্রপ-শ্যাডো পড়বে যাতে ইউজার বুঝতে পারেন নিচে ডাটা স্ক্রোল হচ্ছে।

### ৪.২ মাল্টি-কলাম সর্টিং ও ফিল্টারিং (Sorting & Filtering)
- হেডারে ক্লিক করলে সাইকেল হবে: `Default` → `Ascending (↑)` → `Descending (↓)` → `Clear`।
- কিবোর্ডের `Shift` চেপে একাধিক কলামে ক্লিক করলে **Multi-Column Sort** কার্যকর হবে (e.g. প্রথমে বায়ার অনুযায়ী, তারপর শিপমেন্ট ডেট অনুযায়ী)।
- প্রতিটি কলামের হেডারে একটি কুইক সার্চ/ফিল্টার আইকন থাকবে যা ক্লিক করলে ইন-লাইন ড্রপডাউন পপওভার ওপেন হবে।

### ৪.৩ কলাম রিসাইজিং ও কলাম ভিজিবিলিটি (Resize & Toggle)
- কলাম হেডারের ডানপ্রান্তে মাউস হোভার করলে রিসাইজ হ্যান্ডেল (`|`) দেখা যাবে; অপারেটর ড্র্যাগ করে কলাম ছোট-বড় করতে পারবেন।
- **Column Visibility Selector:** টেবিলের উপরে ডানে একটি বাটন থাকবে: `Columns (12/15)`। ক্লিক করলে ড্রপডাউন মেনু আসবে যেখানে চেকবক্স টিক/আনটিক করে যেকোনো কলাম সাময়িকভাবে লুকানো যাবে।
- ইউজারের এই কলাম সেটিং ব্রাউজারের `localStorage`-এ অটো-সেভ থাকবে, যাতে পেজ রিফ্রেশ করলেও কলাম পছন্দ নষ্ট না হয়।

### ৪.৪ নেস্টেড রো এক্সপ্যান্ড (Nested Rows / Order Matrix Breakdown)
গার্মেন্টস অর্ডারে একটি পিও-এর ভেতরে একাধিক কালার ও সাইজ ব্রেকডাউন থাকে।
- অর্ডারের রো-এর বামপাশে একটি এক্সপ্যান্ড আইকন (`▶`) থাকবে।
- ক্লিক করলে রোটি মসৃণভাবে নিচের দিকে এক্সপ্যান্ড হবে (`▼`) এবং নিচে একটি সুন্দর **Sub-Table** ওপেন হবে যাতে উক্ত পিও-এর কালার-ওয়াইজ সাইজ রেশিও, কাটিং প্রগ্রেস এবং সুইং কিউসি স্ট্যাটাস দেখা যাবে।

### ৪.৫ ইন-লাইন সেল এডিটিং (Inline Cell Editing)
- অনুমোদিত ফিল্ডে (যেমন: সুইং লাইনে দৈনিক রিভাইজড টার্গেট বা কাটিং প্ল্যানের লেয়ার কাউন্ট) সেলে **ডাবল ক্লিক** করলে সেটি ইনপুট বক্সে পরিণত হবে।
- কিবোর্ডের `Enter` চাপলে তাৎক্ষণিক ডাটা সেভ হয়ে ভ্যালিডেশন নোটিফিকেশন আসবে।
- `Esc` চাপলে পূর্বের মানে ফিরে যাবে।

### ৪.৬ বাল্ক সিলেকশন ও ফ্লোটিং অ্যাকশন বার (Bulk Selection Floating Bar)
- টেবিল হেডারের চেকবক্সে ক্লিক করলে পুরো পেজের সব রো সিলেক্ট হবে।
- এক বা একাধিক রো সিলেক্ট হওয়ার সাথে সাথে পেজের নিচে কেন্দ্রস্থলে একটি প্রিমিয়াম **Floating Action Bar** ভেসে উঠবে:
  ```
  ┌────────────────────────────────────────────────────────────────────────┐
  │  [✓] 15 Orders Selected   │  [Approve Selected]  [Export Excel]  [✕]   │
  └────────────────────────────────────────────────────────────────────────┘
  ```
- এখান থেকে এক ক্লিকে বাল্ক স্ট্যাটাস চেঞ্জ, বাল্ক পিও অনুমোদন বা বাল্ক বারকোড প্রিন্ট দেওয়া যাবে।

### ৪.৭ এক্সপোর্ট ইঞ্জিন (Client & Server-Side Export)
টেবিলের উপরে `Export` বাটনে ক্লিক করলে দুটি বিকল্প থাকবে:
1. **Excel (.xlsx):** বর্তমান টেবিলে যে কলামগুলো চালু আছে এবং যে ফিল্টার অ্যাপ্লাই করা আছে, হুবহু সেই ফিল্টারকৃত ডাটা ফরম্যাটেড স্প্রেডশিট আকারে ডাউনলোড হবে।
2. **PDF Report:** কারখানার ফ্লোর অডিট বা মার্চেন্ডাইজিং মিটিংয়ের জন্য লোগো ও হেডার সহ প্রিন্ট-রেডি ফরম্যাট তৈরি হবে।

## ৬. টাইপস্ক্রিপ্ট কম্পোনেন্ট কন্ট্রাক্ট (TypeScript Interface)

```typescript
import { ColumnDef, RowSelectionState, SortingState } from '@tanstack/react-table';

export interface DataTableProps<TData> {
  columns: ColumnDef<TData, any>[];
  data: TData[];
  isLoading?: boolean;
  totalCount?: number;
  pageSize?: number;
  currentPage?: number;
  onPageChange?: (page: number) => void;
  onPageSizeChange?: (size: number) => void;
  onSortingChange?: (sorting: SortingState) => void;
  onRowSelectionChange?: (selectedRows: TData[]) => void;
  isVirtual?: boolean;
  density?: 'compact' | 'standard'; // 'compact' = 40px, 'standard' = 52px
  pinnedLeftColumns?: string[];     // e.g. ['order_number', 'buyer_name']
  pinnedRightColumns?: string[];    // e.g. ['actions']
  renderSubRow?: (row: TData) => React.ReactNode; // For nested expandable row
  bulkActions?: React.ReactNode;   // Action buttons inside floating bar
  onExportExcel?: () => void;
  onExportPdf?: () => void;
}
```

## ৭. ডেভেলপার গাইডলাইন ও নিয়মাবলী

1. **কোনো কাস্টম টেবিল নয়:** প্রজেক্টের কোথাও নতুন করে `<table>` ট্যাগ দিয়ে টেবিল তৈরি করা কঠোরভাবে নিষিদ্ধ। সর্বদা `@/components/ui/table` ব্যবহার করতে হবে।
2. **ভার্চুয়ালাইজেশন বাধ্যবাধকতা:** যে টেবিলে ১০০টির বেশি ডাটা রেন্ডার হওয়ার সম্ভাবনা আছে, সেখানে অবশ্যই `isVirtual={true}` প্রপস পাস করতে হবে।
3. **লোকাল স্টোরেজ কি:** প্রতিটি টেবিল ইনস্ট্যান্সে একটি ইউনিক `tableId` (e.g. `merchandising-orders-table`, `cutting-bundles-table`) থাকবে, যার মাধ্যমে ব্যবহারকারীর কলাম ভিজিবিলিটি সংরক্ষিত থাকবে।
