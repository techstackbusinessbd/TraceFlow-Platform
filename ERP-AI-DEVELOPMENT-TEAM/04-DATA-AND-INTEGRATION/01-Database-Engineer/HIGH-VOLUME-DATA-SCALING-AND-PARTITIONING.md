## ১. ভূমিকা ও স্কেলিং লক্ষ্যমাত্রা (High-Volume Context)

একটি মাঝারি থেকে বৃহৎ আকারের আরএমজি কারখানায়:
- প্রতিদিন কাটিং থেকে গড়ে ৫০,০০০+ বান্ডেল ও পিস কার্ড তৈরি হয়।
- সুইং ফ্লোরের লাইভ ট্র্যাকিংয়ে প্রতিদিন ২,০০,০০০+ থেকে ৫,০০,০০০+ বারকোড স্ক্যান লগ এন্ট্রি হয়।
- বছরে এই ডাটার পরিমাণ দাঁড়ায় **৭ কোটি থেকে ১৫ কোটি (70M - 150M) রেকর্ড**।

এই বিপুল পরিমাণ ডাটা থাকা সত্ত্বেও এপিআই রেসপন্স টাইম **সাব-২০০ মিলিসেকেন্ড** এবং বারকোড স্ক্যানিং গতি **সাব-৫০ মিলিসেকেন্ডে** ধরে রাখতে এই আর্কিটেকচার কার্যকর করা হয়েছে।

## ৩. টেবিল পার্টিশনিং স্পেসিফিকেশন (PostgreSQL 16 Partitioning)

### ৩.১ পার্টিশনড হাই-ভলিউম টেবিলসমূহ:
1. **`sewing_production_logs`**: সেলাই মেঝের প্রতিটি সুইং অপারেশনের স্ক্যান লগ।
2. **`bundle_card_scans`**: কাটিং বান্ডেলের ফ্লোর ট্র্যাকিং ও হ্যান্ডঅফ লগ।
3. **`quality_inspection_logs`**: এন্ড-লাইন এবং ইন-লাইন কিউসি ডিফেক্ট লগ।
4. **`carton_scan_items`**: ফিনিশিং ও কার্টনিং স্ক্যানিং লগ।

### ৩.২ পার্টিশন কৌশল ও DDL ইমপ্লিমেন্টেশন:
```sql
-- মূল টেবিল পার্টিশন বাই রেঞ্জ (scanned_at)
CREATE TABLE sewing_production_logs (
    id UUID NOT NULL,                          -- UUID v7
    sewing_line_id UUID NOT NULL,
    bundle_id UUID NOT NULL,
    piece_serial INT NOT NULL,
    operator_id UUID NOT NULL,
    scanned_at TIMESTAMPTZ NOT NULL,
    status_id UUID NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id, scanned_at)
) PARTITION BY RANGE (scanned_at);

-- মাসিক পার্টিশন টেবিল (চলতি বছর ও মাস অনুযায়ী)
CREATE TABLE sewing_logs_2026_09 PARTITION OF sewing_production_logs
    FOR VALUES FROM ('2026-09-01 00:00:00+06') TO ('2026-10-01 00:00:00+06');

CREATE TABLE sewing_logs_2026_10 PARTITION OF sewing_production_logs
    FOR VALUES FROM ('2026-10-01 00:00:00+06') TO ('2026-11-01 00:00:00+06');

-- পার্টিশন প্রুনিং নিশ্চিত করতে কম্পোজিট ইনডেক্স
CREATE INDEX idx_sewing_logs_line_scan ON sewing_production_logs (sewing_line_id, scanned_at DESC);
CREATE INDEX idx_sewing_logs_bundle ON sewing_production_logs (bundle_id, scanned_at DESC);
```

## ৪. স্বয়ংক্রিয় পার্টিশন ম্যানেজমেন্ট (Automated Partition Maintenance)
- প্রতি মাসের ২৫ তারিখে লারাভেলের সিডিউলড ব্যাকগ্রাউন্ড কমান্ড (`php artisan rgm:partition:create-next-month`) স্বয়ংক্রিয়ভাবে পরবর্তী ৩ মাসের পার্টিশন টেবিল আগে থেকেই ডাটাবেজে তৈরি করে রাখবে।
- কোনো ম্যানুয়াল ইন্টারভেনশনের প্রয়োজন হবে না।

## ৫. ডাটা লাইফসাইকেল ও হট/কোল্ড আর্কাইভিং পলিসি (Archival Policy)

| ডাটা টিয়ার | সময়কাল | স্টোরেজ লোকেশন | পারফরম্যান্স প্রভাব |
|---|---|---|---|
| **হট ডাটা (Hot Data)** | চলতি ০ - ৬ মাস | হাই-স্পিড NVMe SSD (PostgreSQL Primary) | লাইভ প্রোডাকশন ট্র্যাকিং, রেসপন্স টাইম <৫০ms |
| **ওয়ার্ম ডাটা (Warm Data)** | ৬ - ১২ মাস | PostgreSQL রিড-অনলি পার্টিশন | হিস্টোরিক্যাল অডিট ও বায়ার রিপোর্ট |
| **কোল্ড ডাটা (Cold Data)** | ১২+ মাস (অতীতের অর্ডার) | কম্প্রেসড Parquet / S3 কোল্ড স্টোরেজ | স্টোরেজ খরচ ৯০% হ্রাস ও ডাটাবেজ লাইটওয়েট রাখা |

## ৬. কানেকশন পুলিং ও হাই-কনকারেন্সি থ্রেশহোল্ড
- **সমসাময়িক স্ক্যানার সংখ্যা:** একসাথে ২,০০০+ হ্যান্ডহেল্ড বারকোড স্ক্যানার কানেক্টেড থাকতে পারবে।
- **ডাটাবেজ কানেকশন পুলিং:** লারাভেলের অপ্টিমাইজড পুল ও PgBouncer এর মাধ্যমে সর্বোচ্চ ৩০০টি সরাসরি পোস্টগ্রেস কানেকশন দিয়ে ২,০০০+ ক্লায়েন্ট হ্যান্ডেল করা হবে।
