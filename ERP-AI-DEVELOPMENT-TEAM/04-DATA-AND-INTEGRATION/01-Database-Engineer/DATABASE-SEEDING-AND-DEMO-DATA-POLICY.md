# TraceFlow-RMG: ডাটাবেজ সিডিং, ডেমো আইসোলেশন ও সেফ ক্লিনিং আর্কিটেকচার

**Version:** 5.0.0

**Classification:** Database Engineering, Seeding Strategy, Production Data Safety  
**Approved By:** Lead Database Architect & Principal System Engineer

## ১. ভূমিকা ও উদ্দেশ্য (Executive Summary)

এন্টারপ্রাইজ ইআরপিতে প্রায়শই টেস্টিং বা ক্লায়েন্ট ডেমোর জন্য ডামি ডাটা তৈরি করা হয়। কিন্তু কোনো সুনির্দিষ্ট আর্কিটেকচারাল বিভাজন না থাকলে:
1. প্রোডাকশনে ভুল করে ডেমো ডাটা সিড হয়ে যায়।
2. পরবর্তীতে ডেমো ডাটা মুছতে গিয়ে সিস্টেমের অপরিহার্য মাস্টার কনফিগারেশন (Core Bootstrap Data) যেমন: সিস্টেম ক্যাটাগরি, ডিফল্ট রোল-পারমিশন, ডকুমেন্ট সিকোয়েন্স রুলস মুছে ডাটাবেজ ক্র্যাশ করে।

TraceFlow-RMG প্ল্যাটফর্মে এই ঝুঁকি চিরতরে বন্ধ করতে **"কোর বুটস্ট্র্যাপ বনাম ট্রানজ্যাকশনাল ডেমো সেপারেশন (Core Bootstrap vs Isolated Demo Isolation)"** নীতি বাস্তবায়ন করা হয়েছে।

## ২. অপরিহার্য নীতিসমূহ (Inviolable Seeding Invariants)

### [RULE-01] অপ্রয়োজনীয় ডেমো সিডার সম্পূর্ণ নিষিদ্ধ (No Unnecessary Demo Seeders)
- ডেভেলপমেন্টের নামে কাল্পনিক শত শত এলোমেলো ডেমো সিডার তৈরি করা সম্পূর্ণ নিষিদ্ধ।
- সিডার ফোল্ডারে শুধুমাত্র সিস্টেমে চালু রাখার জন্য প্রয়োজনীয় মিনিমাম বৈধ মাস্টার ডাটা থাকবে।

### [RULE-02] বুটস্ট্র্যাপ ডাটা বনাম ডেমো ডাটার স্পষ্ট বিভাজন (Strict Seeder Classification)
ডাটাবেজ সিডারকে দুটি সম্পূর্ণ ভিন্ন ক্যাটাগরিতে বিভক্ত করা হয়েছে:

```
database/seeders/
├── bootstrap/                          # [CORE SYSTEM DATA - NEVER DELETE]
│   ├── SystemCategorySeeder.php        # সিস্টেম সেটিংস ক্যাটাগরি ও অপশনস
│   ├── DocumentSequenceSeeder.php      # সেন্ট্রাল ডকুমেন্ট সিকোয়েন্স ও নাম্বারিং রুলস
│   └── RoleAndPermissionSeeder.php     # সুপার অ্যাডমিন, মার্চেন্ডাইজার রোলস ও পারমিশনস
│
└── demo/                               # [SAMPLE / TESTING DATA - 100% ISOLATED & PURGEABLE]
    ├── DemoOrganizationSeeder.php      # স্যাম্পল কোম্পানি (e.g. Standard Group, ITSL)
    ├── DemoBuyerOrderSeeder.php        # স্যাম্পল বায়ার অর্ডার ও স্টাইল
    └── DemoCuttingBundleSeeder.php     # স্যাম্পল কাট প্ল্যান ও বান্ডেল কার্ড
```

## ৩. ডেমো ডাটা আইসোলেশন ফ্ল্যাগ (`is_demo` Indicator)

যেসব টেবিলে ডেমো বা স্যাম্পল ডাটা প্রবেশ করানো হতে পারে (যেমন: `companies`, `buyers`, `styles`, `buyer_orders`, `bundle_cards`), সেই সমস্ত টেবিলে একটি নিবেদিত সেফটি ফ্ল্যাগ রাখা হয়েছে:

```sql
-- ডেমো ডাটা সুনির্দিষ্টভাবে চিহ্নিত করার কলাম
ALTER TABLE companies ADD COLUMN is_demo BOOLEAN NOT NULL DEFAULT FALSE;
ALTER TABLE buyers ADD COLUMN is_demo BOOLEAN NOT NULL DEFAULT FALSE;
ALTER TABLE buyer_orders ADD COLUMN is_demo BOOLEAN NOT NULL DEFAULT FALSE;
```

### কার্যপদ্ধতি:
- ডেমো সিডারের মাধ্যমে কোনো ডাটা ইনসার্ট হলে তা বাধ্যতামূলকভাবে `'is_demo' => true` ফ্ল্যাগ ধারণ করবে।
- এর ফলে সিস্টেম যেকোনো মুহূর্তে এক ক্লিকে বা এক কমান্ডে শুধু ডেমো রেকর্ডগুলো ফিল্টার করে মুছে ফেলতে পারে।

## ৪. সেফ ডেমো ক্লিনার কমান্ড (`php artisan traceflow:purge-demo`)

কখনোই `migrate:fresh` বা কাঁচা `TRUNCATE` চালিয়ে ডেমো ডাটা মোছা যাবে না; কারণ এতে সিস্টেমের কনফিগারেশন নষ্ট হয়ে যায়। 

তার পরিবর্তে একটি ডেডিকেটেড আর্টিসান কমান্ড তৈরি করা হয়েছে:
```bash
docker compose exec -T tf_backend php artisan traceflow:purge-demo
```

### এই কমান্ডের কাজের ক্রম (Cascade Deletion Order):
1. **প্রোডাকশন এনভায়রনমেন্ট গার্ড:** যদি এনভায়রনমেন্ট `APP_ENV=production` হয়, কমান্ডটি কোনোভাবেই রান হবে না (যদি না `--force` এবং অ্যাডমিন কনফার্মেশন পাস করা হয়)।
2. **ডিপেন্ডেন্সি অর্ডার অনুযায়ী শুধু ডেমো ডিলিট:**
   - ধাপ ১: সমস্ত ডেমো বান্ডেল স্ক্যান ও সুইং প্রোডাকশন লগ ডিলিট (`WHERE is_demo = true`).
   - ধাপ ২: সমস্ত ডেমো কাট প্ল্যান ও কাটিং ডাটা ডিলিট (`WHERE is_demo = true`).
   - ধাপ ৩: সমস্ত ডেমো অর্ডার ও সাইজ ম্যাট্রিক্স ডিলিট (`WHERE is_demo = true`).
   - ধাপ ৪: সমস্ত ডেমো স্টাইল ও বায়ার ডিলিট (`WHERE is_demo = true`).
   - ধাপ ৫: সমস্ত ডেমো কোম্পানি ও প্ল্যান্ট ডিলিট (`WHERE is_demo = true`).
3. **কোর বুটস্ট্র্যাপের শূন্য ক্ষতি (Zero Impact Guarantee):**
   - `system_categories` এবং `system_options` সম্পূর্ণ অক্ষত থাকবে।
   - `document_sequences` (নাম্বারিং প্যাটার্ন ও কাউন্টার রুলস) অক্ষত থাকবে।
   - `roles` এবং `permissions` অক্ষত থাকবে।
4. **রেডিস ক্যাশ পার্জ:**
   - ডেমো ডাটা মুছে যাওয়ার সাথে সাথে সংশ্লিষ্ট রেডিস ক্যাশ ট্যাগগুলো ফ্লাশ হয়ে ফ্রেশ স্টেটে ফিরে যাবে।

## ৫. এক্সিকিউশন ও সিডিং কমান্ডের মানদণ্ড

| কাজের ধরন | কমান্ড | ফলাফল |
| :--- | :--- | :--- |
| **নতুন সার্ভার ইনিশিয়ালাইজেশন (Zero Demo)** | `php artisan db:seed --class=SystemBootstrapSeeder` | শুধু কোর সিস্টেম সেটিংস, পারমিশন ও সিকোয়েন্স সিড হবে। একটিও ডেমো ডাটা ঢুকবে না। |
| **লোকাল টেস্ট বা ক্লায়েন্ট ডেমো সিডিং** | `php artisan db:seed --class=DemoDataSeeder` | শুধুমাত্র টেস্টিংয়ের জন্য নিরাপদ আইসোলেটেড ডেমো ডাটা সিড হবে (`is_demo=true`)। |
| **ডেমো ডাটা সম্পূর্ণ নিরাপদভাবে মোছা** | `php artisan traceflow:purge-demo` | সিস্টেম রুলস ও কোর টেবিল ঠিক রেখে শুধু ডেমো ডাটা ১০০% ক্লিন হয়ে যাবে। |

## ৬. অডিট ও কমপ্লায়েন্স গার্ডরেইল

1. **কোনো সিডারে হার্ডকোডেড ক্রেডেনশিয়াল নয়:** সিডারে কখনোই লাইভ পাসওয়ার্ড বা গোপন কি রাখা যাবে না।
2. **অটো-জেনারেটেড কোড ব্যবহার:** ডেমো সিডারেও কোনো কোড ম্যানুয়ালি ইনপুট দেওয়া নিষিদ্ধ; ডেমো ডাটাও সেন্ট্রাল `CodeGeneratorService` দিয়ে নিয়মমাফিক কোড ধারণ করবে।
3. **অনুমোদন ছাড়া ডেমো ফাইল যুক্ত করা নিষিদ্ধ:** যেকোনো নতুন সিডার ফাইল যুক্ত করার পূর্বে সলিউশন আর্কিটেক্ট ও লিড ডিবিএ-র অনুমোদন নিতে হবে।
