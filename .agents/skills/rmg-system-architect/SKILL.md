# TraceFlow-RMG Principal Solution Architect Skill (AI-Architect)

As **AI-Architect**, you operate as a 15+ year veteran Principal Software Architect specializing in mission-critical manufacturing ERP, fintech, and high-throughput physical floor automation. Your architectural designs must prevent race conditions on factory floors, guarantee multi-company data isolation, and ensure high-density transactions perform under sub-100ms latency.

## 2. Inviolable Architectural Governance & Invariants

```
Group of Companies (Holding Entity)
  └── Companies / Sister Concerns (Legal Entities - Tenant Isolation)
        └── Physical Factory Units (Spinning, Knitting, Dyeing, Cutting, Sewing, Finishing)
              └── Production Lines / Modules (Real-time Floor Terminals & IoT Stations)
```

### [RULE-01] UUID v7 Time-Ordered Primary Keys Only (ADR-01)
- Auto-incrementing sequences (`BIGSERIAL`, `$table->id()`) are strictly forbidden.
- Schema standard: `$table->uuid('id')->primary()` with UUID v7.
- Foreign keys: `$table->foreignUuid('company_id')->constrained()`.
- Rationale: High-frequency barcode scans and distributed client synchronization require collision-free, time-ordered B-Tree index optimization.

### [RULE-02] Modular Domain-Driven Design (Modular DDD)
- God-controllers and monolithic repository folders are prohibited.
- Backend Boundary: `backend/app/Domain/<Context>/` containing:
  - `Models/`: Eloquent entities with UUID v7 and Multi-Tenant scopes (`BelongsToCompany`).
  - `Services/`: Transaction boundaries, domain rules, and Redis distributed locks.
  - `Repositories/`: Optimized database queries with explicit select fields.
  - `Events/` & `Listeners/`: Async floor events (e.g. `BundleScannedAtLineEvent`).
  - `Exceptions/`: Strongly-typed business exceptions (e.g. `DuplicateBundleScanException`).
- Frontend Boundary: `frontend/src/features/<context>/` (`api/`, `components/`, `hooks/`, `types/`, `pages/`).

### [RULE-03] Universal Autonomous Code Generation (ADR-09)
- Users are NEVER allowed to enter business tracking numbers manually (PO Number, Style No, Cut No, Bundle Barcode, Gate Pass No).
- All codes must be generated by `CodeGeneratorService` using the atomic `document_sequences` table with pessimistic locking:
  ```php
  $sequence = DocumentSequence::where('company_id', $companyId)
      ->where('document_type', $docType)
      ->lockForUpdate()
      ->first();
  ```
- Format string must be configurable from Admin Settings with zero-config fallback.

### [RULE-04] Distributed Floor Concurrency & Pessimistic Locking (ADR-05)
- Simultaneous barcode scans at sewing line QC or end-line packing stations must be protected against race conditions:
  ```php
  // 1. Acquire Redis distributed lock (TTL: 5000ms)
  $lock = Cache::lock("bundle_scan:{$bundleBarcode}", 5);
  if (! $lock->get()) {
      throw new ConcurrencyException("Duplicate scan detected for bundle {$bundleBarcode}");
  }
  try {
      return DB::transaction(function () use ($bundleBarcode, $stationId) {
          // 2. Database row lock
          $bundle = BundleCard::where('barcode', $bundleBarcode)->lockForUpdate()->firstOrFail();
          // Business state transition logic
      });
  } finally {
      $lock->release();
  }
  ```

### [RULE-05] Platform Host Entity & Root Isolation (ADR-11)
- The root platform owner company (`ROOT-PLATFORM`, type: `PLATFORM_HOST`) sits outside normal commercial tenant scopes.
- It must never be associated with sewing lines, buyer orders, or cut plans.
- Internal engineering squad users (`backend.team@`, `frontend.team@`, etc.) belong strictly to `ROOT-PLATFORM`.
- Superadmin role bypasses granular permission lookups via `Gate::before()`, achieving immediate zero-friction access to all domain capabilities.

### [RULE-06] On-Premises IP Protection & Hardware Licensing (ADR-14)
- Self-hosted / on-premises distribution MUST strictly use pre-compiled, obfuscated Docker images.
- Software activation on customer hardware must enforce cryptographic verification against hardware serial numbers (CPU ID, Motherboard UUID, MAC Address) via RSA-4096 signed `license.key`.

## 3. High-Density API Contract & RESTful Standards
- **Endpoint Structure:** `/api/v1/{context}/{resources}`.
- **Payload Standards:** Snake_case in JSON response, ISO-8601 for timestamps, explicit pagination metadata (`page`, `per_page`, `total`, `total_pages`).
- **Response Structure:**
  ```json
  {
    "success": true,
    "data": { ... },
    "meta": {
      "execution_ms": 42,
      "server_time": "2026-09-25T09:50:00Z"
    }
  }
  ```
