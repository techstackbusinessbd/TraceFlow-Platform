## ১. প্রসঙ্গ ও সমস্যা বিবৃতি (Context & Problem Statement)
ট্রেসফ্লো-আরএমজি প্ল্যাটফর্মটি AI-সহায়তায় অত্যন্ত দ্রুতগতিতে এবং টেস্ট-ড্রিভেন পদ্ধতিতে (TDD) ডেভেলপ করা হচ্ছে। ফিচার ডেভেলপমেন্ট, ডাটাবেস মাইগ্রেশন স্ক্রিপ্ট যাচাইকরণ, পারফরম্যান্স বেঞ্চমার্কিং, এবং ইউনিট বা এন্ড-টু-এন্ড টেস্ট চলাকালীন সময়ে ডেভেলপার এবং AI এজেন্টকে প্রায়শই সাময়িক টেস্ট ফাইল, স্ক্র্যাচ স্ক্রিপ্ট, ডামি লগ, প্রিভিউ ফাইল বা টেম্প ডাটা ডাম্প তৈরি করতে হয়।

যদি এই ফাইলগুলো কাজ শেষ হওয়ার পর রিপোজিটরিতে অবহেলায় ফেলে রাখা হয়:
1. **রিপোজিটরি ব্লট (Repository Bloat):** অপ্রয়োজনীয় ডামি টেস্ট ফাইল গিট হিস্ট্রিতে ঢুকে কোডবেসের আকার বড় করে তোলে।
2. **গারবেজ ও ডেড কোড (Garbage & Dead Code):** অকেজো কোড বা অপ্রয়োজনীয় ফাংশন পরবর্তী ডেভেলপারদের বিভ্রান্ত করে।
3. **সিকিউরিটি ও ডাটা লিক ঝুঁকি:** সাময়িক ফাইলে কোনো ক্রেডেনশিয়াল বা টেস্ট ডাটা থাকলে তা প্রোডাকশনে পুশ হয়ে যাওয়ার ঝুঁকি থাকে।

## ২. গৃহীত সিদ্ধান্ত (Architectural Decisions)

```
┌────────────────────────────────────────────────────────────────────────┐
│             ZERO GARBAGE & AUTONOMOUS CLEANUP WORKFLOW (ADR-17)        │
│                                                                        │
│   [ 1. Isolated Scratch Zone ]       [ 2. Autonomous Post-Task Wipe ]   │
│   All temp scripts in scratch/       Immediate rm/unlink upon complete  │
│                                                                        │
│   [ 3. Strict .gitignore Shield ]    [ 4. Pre-Commit Hygiene Scan ]     │
│   Auto-ignores *.tmp, *.log, test_*  Block commit if temp artifacts exist│
└────────────────────────────────────────────────────────────────────────┘
```

### [DECISION-01] আইসোলেটেড সাময়িক স্ক্র্যাচ ডিরেক্টরি (Designated Scratch Zone)
1. **প্রজেক্ট রুট বা সোর্স কোডের ভেতরে কোনো টেম্প ফাইল তৈরি করা সম্পূর্ণ নিষিদ্ধ।**
2. টেস্টিং, স্ক্রিপ্টিং বা ওয়ান-অফ ট্রায়ালের প্রয়োজনে ফাইল তৈরি করতে হলে শুধুমাত্র নিচের নির্দিষ্ট স্থানে রাখতে হবে:
   - AI Artifacts Scratch: `<appDataDir>\brain\<conversation-id>/scratch/`
   - প্রজেক্ট লোকাল ড্রাফট (যদি নিতান্তই দরকার হয়): `storage/temp/` (যা ইতিমধ্যে গিট-ইগনোরড)।

### [DECISION-02] অটোনোমাস পোস্ট-টাস্ক ক্লিনআপ (Immediate Post-Task Purge)
1. **কাজ শেষের সাথে সাথে ডিলিট:** কোনো টেস্টিং, মাইগ্রেশন ট্রায়াল বা ভ্যালিডেশন স্ক্রিপ্ট রান হওয়ার কাজ সফলভাবে সম্পন্ন হওয়ামাত্রই সেই টেম্প ফাইল, লগ ও ডামি আউটপুট ফাইল **তাত্ক্ষণিকভাবে মুছে ফেলতে হবে (Delete/Unlink)**।
2. **জিরো গারবেজ কোড পলিসি:** 
   - কোনো টেস্ট ফাংশন বা ডিবাগ কোড (`dd()`, `dump()`, `console.log()`, `var_dump()`) সোর্স কোডে ফেলে রাখা যাবে না।
   - কোনো কমেন্টেড-আউট পুরনো কোড (`// dead code block`) রাখা নিষিদ্ধ; প্রয়োজনে গিট হিস্ট্রি ব্যবহার করতে হবে।

### [DECISION-03] .gitignore গার্ডরেল ও ফাইল প্যাটার্ন ব্লকিং
নিচের সব ধরণের সাময়িক এক্সটেনশন এবং ফোল্ডারকে রিপোজিটরি লেভেলে শক্তভাবে ইগনোর ও ব্লক রাখতে হবে:
```gitignore
# Temporary scratch & test artifacts
*.tmp
*.temp
storage/temp/*
storage/testing/*
.phpunit.cache/
npm-debug.log*
yarn-debug.log*
yarn-error.log*
test-reports/
coverage/
```

### [DECISION-04] প্রি-কমিট হাইজিন ভ্যালিডেশন (Pre-Commit Hygiene Check)
গিট কমিট করার আগে এজেন্টকে অবশ্যই নিশ্চিত করতে হবে:
1. `git status` এ কোনো আনট্র্যাকড টেম্প ফাইল বা টেস্ট স্ক্র্যাপ নেই।
2. কোনো সোর্স ফাইলের ভেতরে সাময়িক টেস্ট লজিক বা ডামি ভ্যারিয়েবল থেকে যায়নি।
3. সব কোড সম্পূর্ণ ক্লিন, প্রোডাকশন-রেডি এবং স্ট্যান্ডার্ড ডোমেইন লেয়ারে অবস্থিত।

## ৩. সুফল ও প্রভাব (Business & Technical Benefits)
1. **ক্লিন ও প্রফেশনাল রিপোজিটরি:** কোডবেস সবসময় ১০০% পরিচ্ছন্ন এবং সিনিয়র ইঞ্জিনিয়ার-লেভেল হাইজিন বজায় থাকে।
2. **জিরো টেকনিক্যাল ডেট:** অপ্রয়োজনীয় ডামি স্ক্রিপ্ট জমে সিস্টেম জটিল হওয়ার কোনো সুযোগ থাকে না।
3. **কনফিউশন-মুক্ত টিমওয়ার্ক:** অন্য কোনো ইঞ্জিনিয়ার বা সিস্টেম অডিটর কখনোই কোনো পরিত্যক্ত বা বিভ্রান্তিকর টেস্ট কোড দেখতে পাবে না।
